# Разработка и обновление skill

## Порядок работы

1. Работать в отдельном fork/clone, а не редактировать установленный skill как единственный источник: репозиторий должен оставаться воспроизводимым.
2. Перед изменением поведения написать тест и увидеть ожидаемое падение. Минимальные обязательные проверки:
   - установщик копирует skill в `${HERMES_HOME:-$HOME/.hermes}/skills/smart-home/yandex-station-speak`;
   - повторная установка сохраняет существующий `.env` и возвращает ему права `0600`;
   - `speak.sh` определяет каталог относительно собственного файла, а не жёстко через `$HOME`, иначе profiles и нестандартный `HERMES_HOME` ломаются;
   - OAuth helper заменяет только `MUSIC_TOKEN`, не меняя остальные значения `.env`, отклоняет симлинк и атомарно заменяет файл через временный файл с правами `0600`;
   - если исходную громкость или состояние плеера прочитать не удалось, аудиоцикл завершается до паузы/смены громкости — подставное значение нельзя потом считать исходным;
   - при ошибке отправки аудиоцикл в `finally` возвращает громкость и продолжает музыку только если она играла до сообщения;
   - при нестандартном `HERMES_HOME` все команды README/SKILL и установленный `speak.sh` используют активный profile, а не жёсткий `~/.hermes`;
   - если Python младше версии, нужной OAuth helper, установщик не печатает команду с несуществующим `.token-venv`, а явно сообщает, что настройка токена не завершена.
3. Для получения `MUSIC_TOKEN` использовать OAuth Device Flow через `ya-passport-auth`; сохранять токен прямо в `.env` и не печатать его в терминал или чат. Основной TTS работает на Python 3.10+, а актуальный auth helper требует Python 3.12+, поэтому держать его в отдельном `.token-venv`.
4. Список устройств получать через `--list-devices`, затем переносить точные `id` и `platform` без нормализации. IP брать из DHCP leases и закреплять статическим lease.
5. Считать `conversationToken` примерно 30-минутным и обновлять через 25 минут. Не сокращать кэш до 25 секунд из-за ошибочного текста в старой документации.
6. Перед завершением выполнить:

```bash
python3 -m unittest discover -s tests -v
bash -n install.sh speak.sh
python3 -m py_compile scripts/tts_dialog.py get_music_token.py
./install.sh
```

7. После установки проверить реальную колонку короткой нейтральной фразой. Успешные unit-тесты не проверяют совместимость с текущей прошивкой Glagol.
8. Просканировать tracked diff на `MUSIC_TOKEN`, реальные `DEVICE_ID` и локальные адреса пользователя. В README использовать заведомо примерные значения.

## Питфолы

- Не клонировать исходный Claude skill внутри `install.sh`: установщик fork должен копировать собственные файлы, иначе устанавливается другая кодовая база и локальные исправления теряются.
- Не восстанавливать звук только после успешной отправки: сетевой сбой между паузой и TTS оставляет колонку на изменённой громкости; восстановление должно находиться в `finally`.
- Не скрывать ошибку `getState` значениями вроде громкости `0.5` или `is_playing=False`: после изменения колонки такие догадки приводят к ложному «восстановлению»; прерывать цикл до первого изменения.
- Не считать `playerState: null` ошибкой чтения: это ответ про простой колонки (плеер не активен). Для `null` допустимо вернуть `is_playing=False`; отсутствие `state` или недиктовый `playerState` должно прерывать цикл до первого изменения.
- Не записывать токен через обычный `write_text()` с последующим `chmod`: между созданием и сменой прав секрет зависит от `umask`, а прерывание оставляет файл открытым шире; создавать временный файл сразу с `0600`, делать `fsync`, затем `os.replace`, и отклонять симлинки.
- Не отправлять «продолжить», если до сообщения плеер не работал: команда запускает музыку из простоя.
- Не коммитить `.token-venv`, `.env`, `__pycache__` и скомпилированные Python-файлы; исключить их в `.gitignore`.
- Не принимать успех `install.sh` за успех функции: отдельно проверить unit-тесты, синтаксис shell/Python и реальную озвучку.
